# 智学助手移动端 App 方案（v1 草案）

状态：待评审 · 2026-09-06 · 上一版本：无（首份）

## 1. 背景与现状

Web 端已上线：多用户账号体系（JWT 双 token）、按用户隔离的学习计划/内容/测验/批改、
书签、重新生成策略、字号/夜间模式、计划拖拽排序。

现有移动端 = `mobile/` 目录下的 **Capacitor 6 Android 壳**：

- 把 `frontend/` 构建产物装进 WebView（`com.zhixue.app` / 智学助手）；
- 构建时通过 `VITE_API_BASE` 注入服务器绝对地址（当前允许 HTTP 明文，配合测试环境）；
- 产出 `assembleRelease` APK 直接安装，**未签名管理、未上架、无更新机制、无推送、仅 Android**。

痛点：发一个 H5 小改动也要重打 APK 重装；用户没有回访触达手段；清缓存即丢登录后的离线体验；
正式上线后这些都会被放大。

## 2. 目标与非目标

目标（本期）：
- G1 Android 正式可分发：签名、版本管理、更新机制、合规上架（或官网直装）。
- G2 体验补齐：推送提醒、内容离线、微信/QQ 分享、HTTPS 收口。
- G3 一套代码：H5 与 App 共用 `frontend/`，原生能力全走 Capacitor 插件，不为 App 另起炉灶。

非目标（本期）：iOS（见 §7 决策点）、原生重写、微信小程序（等公司主体，作为二期）、平板专门适配。

## 3. 技术路线对比

| 路线 | 复用度 | 成本 | 推送/原生生态 | 结论 |
| --- | --- | --- | --- | --- |
| **A. 深化现有 Capacitor**（推荐） | frontend 100% 复用 | 低（按周计） | 插件生态够用（Push/Share/Filesystem/App Update） | ✅ 本期路线 |
| B. Flutter / RN 重写 | 仅 API 层 | 高（人月级，双端学习成本） | 最好 | 内容型 App 不值当 |
| C. 微信小程序 | API 层复用，UI 重写 | 中 | 微信生态最强 | 二期：等公司主体（注册/登录/分享都依赖它） |

判断依据：zhixue 是"内容渲染 + 表单交互"型应用，H5 层近期功能（书签、编辑、SSE 流式渲染）
全部可直接进 App；原生需求集中在推送/分享/文件三件事，插件即可覆盖。

## 4. 发布与更新策略（M1 核心）

1. **正式签名**：生成 release keystore（妥善备份——丢了就永远无法再更新同一 App）；
   `versionCode` 递增、`versionName` 语义化。
2. **API 收口**：App 一律指向正式 HTTPS 域名（www.ailearningagent.xyz），关闭 `cleartext`；
   测试环境地址仅保留在 debug 包。
3. **热更新（H5 层）**：启动时请求后端 `version.json`，比对后下载新 `www` 资源包覆盖本地——
   H5 改动不再需要重发 APK；仅原生插件/权限变更才发新 APK。注意：若走应用市场上架，
   热更新需符合其规则；官网直装无此限制。
4. **合规**：App 备案（挂靠主体 ICP 备案下提交）、隐私政策页面、首次启动隐私同意弹窗、
   权限最小化（本期只需网络权限）。

## 5. 功能规划

**P0（发布必做，M1）**
- 正式签名 + 应用图标 + 启动页；HTTPS 收口；版本检查与更新提示
- 隐私政策 + 首次启动同意弹窗；崩溃兜底（WebView 白屏检测 + 重载）

**P1（内测→公测，M2/M3）**
- 内容离线缓存：已生成内容本地化（Capacitor Filesystem + SQLite），无网可复习
- 学习提醒推送：国内安卓厂商通道碎片化（华为/小米各需开发者后台），建议接聚合推送
  （极光/个推）或先做"站内提醒 + 每日固定时间本地通知"过渡
- 微信/QQ 分享：学习卡片（计划完成度/成绩），依赖 SDK key 申请

**P2（按用户反馈排期）**
- TTS 听书模式；拍照/文件上传作为学习资料（对接已有 materials 生成模式）；
  桌面小组件（今日任务）；HarmonyOS 适配验证

## 6. 里程碑

| 里程碑 | 内容 | 周期 |
| --- | --- | --- |
| M1 可分发 | 签名/图标/HTTPS/隐私政策/备案提交/更新检查 | ~1 周 |
| M2 内测 | 热更新 + 离线缓存 | ~2 周 |
| M3 公测 | 推送 + 分享 | ~2 周 |
| M4 上架 | 软著办理（2~4 周，与 M2/M3 并行）→ 各市场审核 | 提交后 ~1-2 周 |

## 7. 需要拍板的决策点

1. **分发方式**：官网直装 APK（最快、无审核）vs 国内应用市场（曝光+可信度，需软著+备案）vs 两者都要——建议先官网直装（M1 即可完成），市场作为 M4。
2. **iOS**：开发者账号 $99/年 + 苹果审核 + Capacitor iOS 工程维护。建议等 Android 数据证明有 iOS 用户需求再启动；若有明确需求，M3 后评估。
3. **小程序二期**：需要公司主体（此前 deferred 的原因）。主体就绪后按 §3-C 路线启动。
4. **推送预算**：聚合推送服务有免费额度（极光/个推），超过后按量付费；或先零成本用本地通知过渡。
